# 跨供应商切换不断上下文 — 最终方案（lk-harness）

> 状态：已评审，动手。核心就四步：**导出 → 清目标 → 铺进去 → 开聊**，外加一条护栏：**空导出不清空目标**。

## 1. 一句话

切供应商 = 换个家。规矩：出门必带上全部家当（导出现在家的轮次），进门先腾地方再铺（清目标家、铺轮次），两边对称；手里没东西进门，就别动人家里摆设（空导出不清空，直接续目标原生）。

## 2. 为啥这样定（拍过的结论）

- 不找旧模型写总结：旧供应商常是挂了才切，让它生成等于找哑巴带路，还多花钱。只搬原文轮次。
- 不玩“不进聊天记录”：`llm` 的 system 技巧、`SDK` 的认戳全砍掉，注入就是正常聊天记录的一部分，两边对称，无标记、无比较、无归档。
- 传话游戏不存在：搬的是原文不是摘要，下次带回来还是原文，最多截断丢尾。
- 反复横跳不丢东西，但两边各记一段（分叉），所以切换当偶发操作，别当日常路由。

## 3. 流程（四步 + 一护栏）

```
A(有轮次) ──1.导出A轮次──▶ 手里有货?
                              │有            │空（A空会话 / 上次没搬成）
                              ▼              ▼
                        2.清目标B        2'.不清B，直接续B原生
                        3.铺轮次进B
                        4.开聊
```

- `A→B`：导 `A`，清 `B`，铺 `B`，开聊。`B→A`：导（`A`旧轮次+`B`新聊的），清 `A`，铺 `A`。
- 护栏拆解：
  - 正常搬成的家不可能空；空只来自“上次没搬成”（新家没起来）或“源头本来就是空会话”。
  - 防的是连环事故：`A→B` 失败（`B` 空）→ 再切回 `A`，空账本不能把 `A` 的 100 轮清掉。
- 截断：全文预算 8k 字符，超了丢最旧的；任务首轮常驻（首轮一般是任务目标）。

## 4. 注入形式

- 纯文字轮次（`[用户]/[助手] + 正文`），工具调用过程带不过去，本来也不在搬运范围。
- 一次一整块，跟切换后首条正常消息同回合交付，不拆多条（多条等于伪造多轮发言，还会和真消息穿插）。
- `llm` 侧：首回合 prompt 里独立 `[历史搬运]` 段；`SDK` 侧：新会话首回合任务位。消费即生效，无需二次清理。

## 5. 存储改动（两处小手术）

1. **会话级资源路由**（镜像 `session-model-store`）：新文件 `session-resource-overrides.json`，`set/get/clear/resolve` 四件套；`launchAgent`（`electron/session-dispatcher.ts`）解析资源改为 `override → 通道默认`。模型解析不动。
2. **`llm` 的 `pi` 文件按“会话+供应商”分家**：`sessionDirForKey` 的 key 从 `sessionKey` 改成 `sessionKey + 生效resourceId`，资源不变 key 不变（老会话原地续上，无感）；一切换就是天然新家，“清目标”对 `llm` 等于建新目录，无需删文件。`SDK` 侧“清目标”=`forget` 该会话映射（只清映射，不碰后端）。

## 6. 指令 `/m p`（会话级，不碰通道默认，沿用 `/m` 的门）

```
/m p ls                          列供应商（名称/类型/当前 tag）
/m p set <序号|id> [--model <id>] 切当前会话供应商；--model 缺省走通道默认/auto
/m info                          加一行：对话供应商 + 搬运状态
```

- `set` 只写 override + 停旧 worker（**切走那家原样保留**），下次该会话有消息时走四步流程拉起；回执写清“只影响当前对话”。
- 通道默认供应商仍在设置页改（影响未来会话）。

## 7. 路径行为（全收敛到四步）

| 切换 | 行为 |
|---|---|
| llm A→B（含 builtin↔custom） | 导A → 新目录（清目标）→ 铺 → 开聊 |
| sdk↔llm | 同上；`SDK` 清目标=`forget` 映射 |
| 源头空（新会话/上次失败） | 不清目标，直接按目标原生起，并明示“无历史可搬” |
| 旧供应商挂了导不出 | 同上：不清不搬，明示；老家原样保留，可手工复制 |
| 切回 | 同四步，来回对称 |

## 8. 测试

- store 单测： resource override 的 set/get/clear/回落通道默认。
- 组装单测：截断 8k、空历史、首轮常驻、工具块过滤。
- e2e：项目群 `llm→llm` 切后新引擎说得出旧任务目标；`sdk→llm` 同；失败路径（新供应商 key 错）老家可续。
- 门禁沿用既有用例（`dc0089d`）。

## 9. 非目标

- 工具内部态搬运；`sdk` 换账号（不同 `apiKey`）续旧 `agentId`；搬运逐字 fidelity；`--smart` 摘要（已砍）。
